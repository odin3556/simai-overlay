# 譜面重ね表示ツール v0.2（simai overlay）

YouTube の譜面確認動画の上に透明な層を重ね、simai のノーツを動画と重ねて確かめる Chrome 拡張機能です。
動画から simai の下書きを作ることもできます。
設定は動画ごとに `chrome.storage` に保存します。外へ通信するのは、① で曲を探すときに [OTOGE DB](https://otoge-db.net/maimai/) の曲の一覧（`music-ex.json`）を取りに行くときだけです（1 日はしまっておいた物を使う。動画や譜面の情報は送らない）。

## フォルダの構成

```
simai-overlay/
├─ extension/            Chrome に読み込むのはこのフォルダ（manifest.json がある）
│  ├─ manifest.json
│  ├─ background.js      アイコンのオン / オフ、OTOGE DB の曲の一覧
│  ├─ content.js         全体のつなぎ
│  ├─ lib/               DOM を使わない部分（Node のテストからも読む）
│  │  ├─ simai/          simai を読む・拍を秒に直す
│  │  ├─ geometry/       位置・センサーの区画・スライドの軌道・光り方
│  │  ├─ detect/         動画のコマから見つける（円・最初のノーツ・重なり・スライド・タッチ・下書き）
│  │  └─ songdb.js       曲の情報（OTOGE DB）
│  └─ ui/                ページに出す部分（層・パネル・円合わせ・音・YouTube 依存）
├─ test/                 テスト（node --test）と fixtures/ の譜面
├─ tools/                開発用の道具（Docker で動かす）
│  ├─ youtube-check.mjs  Docker の Chromium で YouTube 上の動作を撮る
│  ├─ preview/           動画なしでパネルの見た目を撮るページ
│  ├─ radar/             譜面レーダー試作（Majdata Net の中継つき）
│  └─ *-draft.js 他       下書きと答えの譜面を比べる
├─ docs/                 マニュアル・デザイン案・協力者募集
├─ compose.yaml          テストと道具を Docker で動かす設定
└─ .check/               youtube-check の出力（git には入れない）
```

新しいファイルを足すときは、DOM を使わない計算なら `extension/lib/` の近い所、画面に出すものなら `extension/ui/` に置き、`extension/manifest.json` の `js` の並び（読み込む順）にも足します。

## v0.2 で増えたこと

- ① 曲を探して選ぶ: OTOGE DB から BPM・難易度・譜面作者・ノーツの数を読み、⑥ の BPM に入れる。gamerch の曲のページへのリンクも出す。
- ④ 最初のノーツの自動検出（「▶ 再生して自動で探す」）。
- ⑥ 動画から simai の下書き（タップ・ホールド・星・BREAK）。① の曲を選んでいれば、先頭に曲の情報をコメントで書き、公式のノーツの数と見比べる。
- スライドの軌道（矢印と、軌道を進む星）と、タッチホールド（虹の三角と、満ちていく輪）の描画。
- パネルの手順を ①〜⑥ に並べ直した。
- いまの場所: パネルの上に、再生時間・譜面の時刻・小節と拍・simai の何行目かと、その行のいまの区切り（黄色）を出す。「② で選ぶ」で、② の欄のその区切りを選ぶ。同じものを動画の左上にも出す（「場所を動画に」で消せる）。
- 円を手で合わせるとき、マウスを止めて YouTube が操作バーを隠すと十字のカーソルにならないことがあったのを直した。

## Chrome への読み込み

1. Chrome のアドレス欄に `chrome://extensions` と入力して開く。
2. 右上の「デベロッパー モード」をオンにする。
3. 「パッケージ化されていない拡張機能を読み込む」を押し、`extension` フォルダ（`manifest.json` があるフォルダ）を選ぶ。
4. YouTube を開く（開いていたら再読み込み）。拡張機能のアイコンを押すと、層とパネルが出る。
   アイコンが見えないときは、パズルの形のアイコンから「譜面重ね表示」をピン留めする。
5. ファイルを差し替えたら、拡張機能の一覧でカードの「更新」（円形の矢印）を押し、YouTube を再読み込みする。

## 使い方（OV3RCLOCK 14+ の例）

1. https://www.youtube.com/watch?v=VjAMhNeq0Nk を開き、アイコンを押す。
   ① で「動画のタイトルから」を押すと、OTOGE DB から「OV3RCLOCK」「でらっくす MASTER 14+」が選ばれ、BPM 118・ノーツ 927 と出る。
   曲名で探すときは、曲名・読み・アーティストを入れて「探す」。違う難易度は下の一覧で選び直す。一度読んだあとは、新しい動画を開くと、タイトルから自動で選んでおく。
2. パネルに `test/fixtures/ov3rclock_14plus.simai` の中身を貼り、「読み込む」。
   総数 927・Tap 685・Hold 40・Slide 91・Touch 24・Break 87 と出れば T1 は合格。
3. 円は、新しい動画を開いたときに自動で探す（動画の白い判定線を見つける）。見つかると「円を見つけました」と出て、円と点のガイドが出る。
   再生中に「自動で探す」を押すと、何コマか重ねて探すので、ノーツが多い場面でも確か。
   見つからないとき（判定線が白くない動画など）は、最後に合わせた円か標準の位置（中心が真ん中、半径が高さの 0.445 倍）のまま。
   ずれていれば「円を合わせる」→ 円の中心をクリック → 円のふち（白い線の上）をクリック。
   矢印キーで中心、`+` / `−` で半径を 1px ずつ（Shift で 10px）。Enter で終わる（T3）。
   最後に合わせた円は、次の動画でも初期値になる。「標準の位置に戻す」で戻せる。
4. ④「▶ 再生して自動で探す」を押す。動画の頭から再生し、8 本の線を流れてくるノーツを見つけて first を決める。
   - 最初のノーツが見えると「最初のノーツが 8.800 秒（位置 1・8）に見えました」と出て、そのあと 4 秒ほど再生しながら simai と照らし合わせる。
   - はっきり合えば、その first を使う。合わなければ、最初に見えたノーツに合わせる。どちらも、終わったら止まる。
   - simai を読み込んでいなくても、最初に見えたノーツの時刻を first にする。
   - 曲の始まる前の明るい画面（タイトルなど）は使わない。
   - 手で決めるときは、最初のノーツ（位置 1 と 8 の同時押し）が円に着くコマで止めて「いまが最初のノーツ」。この動画では 8.800 秒のコマ。
     コマ送りは、一時停止中に YouTube の `,`（戻る）と `.`（進む）。
5. パネルの ⑤「▶ 再生して確かめる」を押す（T4・T5）。譜面の始まる少し前から再生し、コマごとに
   「動画のノーツが、重ねたノーツと同じ場所に来ているか」を自動で数える。
   - 叩く瞬間に、円の外側に ○（重なった）か ×（重ならなかった）が出る。
   - パネルに「重なった 36 / 36 ノーツ（100%）」のように出る。緑 85% 以上、黄 60% 以上、赤はそれ未満。
   - first がずれていれば「−3 コマ直すと、よく重なりそう」と出て、「直す」で直せる（±15 コマまで）。
   - 手で直すときは、重ねたノーツが動画より先なら +、遅れていたら −。`[` `]` キーで ±1 コマ、Shift を押しながら（`{` `}`）で ±10 コマ。
   - ずれ探しに使うのはタップ・星・ホールドの頭。タッチ・タッチホールドとスライドは、点ではなくセンサーの区画（`sensors.js`、34 区画）の範囲で見て、別に「タッチ 3/4・スライド 10/12」のように数える（タッチは叩く少し前、スライドは星が動いている間に、その区画の中の星・三角の近くが光っているか）。区画の形はおおよそで、判定のしきい値も動画でまだ確かめていない。
6. 動画から simai の下書きを作る（⑥）。何も貼っていない動画でも使える。
   - ③ の円と ④ の first を決め、BPM を入れて（① で曲を選べば自動で入る）「▶ 再生して下書きを作る」。first の 1 秒前から再生し、最後まで（途中で止めればそこまで）でノーツを拾う。
   - 拾うのはタップ・ホールド（長さも）・星（`$` で書く）・BREAK。スライドの軌道・タッチ・EX はまだ拾わない。BPM が途中で変わる曲にも、まだ対応していない。
   - 拍は 1/12 拍に丸める（16 分も 3 連符も入る）。小節ごとに一番粗い `{n}` を選ぶ。
   - 「② に入れて重ねる」で、下書きを動画に重ね、⑤ で × の出るノーツを探して直す。
   - PC が重いと数えられるコマが減って拾い損ねるので、そのときは YouTube の再生速度を 0.5 にする（何倍速でも動画の時刻で数える）。

別の動画で使ったあと、新しいタブで開き直したり再読み込みしたりして最初からやり直したいときは、② の「この動画をリセット」を 2 回押す（3 秒以内）。
この動画で保存した simai・first・曲・円・下書きが消える。ハイスピ・音・最後に合わせた円など、動画をまたぐ設定は残る。

### パネルの設定

| 設定 | 内容 |
| --- | --- |
| 流れるノーツ | 中心寄りから円へ流れてくるノーツを重ねる |
| ハイスピ・タッチ | 動画を撮ったときのゲームのハイスピ（1〜10、0.25 刻み）。タップは 6.5 で 0.32 秒（この動画）。タッチは別の表で秒に直す |
| アンサー音 | 叩く時刻に短い音を鳴らす（自作の音）。BREAK は高い音が重なる。「ずれ」は正の値で音を遅らせる |
| 円と点のガイド | 円・8 つの点と、タッチセンサーの 34 区画（A1〜A8・B1〜B8・C1・C2・D1〜D8・E1〜E8、点線と名前）を出す |
| タッチの輪 | A〜E の輪の半径の比率（判定線の半径に対する割合）。A 0.832・B 0.46・D 0.881・E 0.648。A・D・E はこの動画で確認 |

この動画の説明には「録画時に音声が入っていなかったため、後付け」とあります。アンサー音は映像に合わせて鳴るので、動画の音とはずれることがあります。

### ノーツの描き方

| ノーツ | 形 | 色 |
| --- | --- | --- |
| タップ | 輪 | ピンク |
| ホールド | 細長い六角形。頭が円に着いたあと、尾が追いつくまで残る | ピンク |
| スライドの始点 | 回る星（`@` を付けると丸いタップ）。1 つの星から 2 本以上出るときは EACH（黄）。星が動いている間は、星のいる区画をうすく塗る | 青 |
| 星形タップ | `$` は回らない星、`$$` は回る星 | 青 |
| スライドの軌道 | 星を叩く少し前から矢印の並びで出す。叩いて 1 拍後に星が軌道を進み、通り過ぎた矢印は消える。同時押しの星から出る軌道は黄 | 青 |
| タッチ | 4 つの三角が寄ってくる。叩く時刻に、その区画（C は C1・C2 の両方）を光らせる | 青 |
| タッチホールド | 4 つの三角を虹の色（赤・黄・緑・青）で描く。押している間は、その区画をうすく塗り、まわりの大きな◆が真上から時計回りに 4 色で形作られていく（◆ができあがる時刻が終わり。simai の書式のページより） | 虹 |
| 同時押し | 形はそのまま | 黄 |
| BREAK | 色の線の内側に白い線 | オレンジ |
| EX | 白く光る縁 | — |

動画のノーツが下に透けて見えるよう、輪郭だけで描きます。
叩く 3 コマ前から薄い輪郭、叩く時刻の ±0.5 コマで濃く光り、そのあと 0.2 秒で消えます。

## テスト（PC に Node を入れずに Docker で）

```
docker compose run --rm test
```

simai の読み込み（T1・T2）と、位置・光り方の計算を確かめます。

```
docker compose run --rm youtube-check
```

パネルの「いま」の帯と動画の左上の表示は、動画を使わないページ `tools/preview/index.html` で見られる: `docker compose run --rm --entrypoint sh youtube-check -c "cp /repo/tools/preview/shot.mjs . && npm init -y >/dev/null && npm i --silent playwright@1.49.1 && node shot.mjs"` で `.check/preview.png` に撮る。
Docker の中の Chromium にこの拡張機能を読み込み、YouTube で動かしてスクリーンショットを `.check/` に撮ります。
下書きを元の譜面と比べるときは、`DRAFT=60 DRAFT_RATE=0.25 FIRST=8.8` で動かしたあと `docker compose run --rm test node tools/compare-draft.js .check/draft.simai test/fixtures/ov3rclock_14plus.simai`。
環境変数（`CALIB`、`SEEK`、`FIRST`、`SHOTS`、`AUTO`、`CHECK`、`FIND`、`DRAFT`、`DRAFT_RATE`、`SONG`）は `tools/youtube-check.mjs` の先頭に書いてあります。
何度も続けて動かすと、YouTube 側で再生できなくなることがあります（2026-10-31 に発生）。

## 設計書との違い・分かったこと

- 譜面の終わりの `E` は 272 拍目（69 小節目の頭）で、約 138.3 秒。設計書の「276 拍・約 140.3 秒」は 69 小節目を丸ごと数えた値。
- `requestVideoFrameCallback` は YouTube で使える。広告中は `#movie_player` に `ad-showing` が付く。
- タッチの位置・ノーツの速さは [HachimiDX](https://github.com/ck2739046/HachimiDX)（maimai の動画から譜面を起こすツール、AGPL-3.0）が調べたゲームの値に合わせた。コードは使わず、数値だけを使っている。
  - 1080p の画面で判定線の半径は 480px（画面の円 540px の 8/9）。ノーツは中心から 120px に現れ、480px まで一定の速さで進む。
  - 進む秒数 = 240 ÷ (ハイスピ × 100 + 100)。タッチは別の表（`flash.js` の `TOUCH_SPEED`）。
  - タッチの中心の座標から比率を出した: A 0.832・B 0.46・D 0.881・E 0.648。以前の初期値（D 0.83・E 0.46）は D・E がずれていた。E3・E1・E7・D1 は 0.881 / 0.648 で動画と重なることを確かめた（10.325 秒・28.376 秒・28.631 秒）。
- 重なりの確認（2026-11-01、Docker の中で 10〜12 秒再生）: first 8.800 秒で 36 / 36 ノーツ・ずれ 0。わざと 3 コマ遅らせた 8.850 秒では 12 / 33・「−3 コマ」と出た。叩く瞬間は白い判定線の上で明るく見えてしまうので、流れてくる途中（叩く 0.26〜0.06 秒前）だけを見ている。
- 円の自動検出は HachimiDX の detect_circle.py の考え方（白黒にして、大きさの決まった丸を探し、何コマか見る）を参考にした。この動画では、止めたコマ（28.376 秒、背景の画像あり）でも再生中でも、中心 0.500, 0.500・半径 0.444 と出た（手で合わせた 0.445、理論値 8/9 × 0.5 = 0.444 と合う）。YouTube の動画のコマは canvas に写して読める。
- 最初のノーツの自動検出（2026-11-01、Docker の中）: 最初に見えたノーツ 8.800 秒・位置 1・8（手で決めた値と同じ）。simai と照らし合わせた first は 8.788 秒（1 コマより小さいずれ）、そのあとの重なりの確認は 29 / 29・ずれ ぴったり。
  - この動画は、0〜6 秒ほどタイトルなどの明るい画面。そこで円を探すと間違える（半径 0.26 など）ので、白い点が 12% より多いコマは円探しに使わない。ノーツ探しでも、線の上が 30% より多く光るコマは使わない。
  - Docker の中の Chromium では、数えられるコマが 3 コマに 1 つほどに減る。1 か所だけ見ると、ノーツが見る場所からずれたコマばかりになって見落とす。そのため線の上を 0.01 秒おきに細かく見ている。
  - simai との照らし合わせは、一番よい候補 0.65 に対し、次の候補が 0.53。「はっきりしている」と決める差 0.1 にあまり余裕がない。
