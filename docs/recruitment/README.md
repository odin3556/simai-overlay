# 共同開発者募集・要望管理（Google フォーム × Discord 通知）

応募も要望も **Google フォーム** で受け付け、**スプレッドシート** で管理します。Discord には Webhook で通知が届くだけで、Discord 上では管理しません。

## 全体の流れ

```
【募集】
Discord で募集フォームURLを案内
   ↓
応募者が Google フォームに入力（Gmail / Discord 名 / Discord ID など）
   ↓ ── Webhook で Discord の #フォーム通知 に「応募がありました」
回答がスプレッドシート「共同開発メンバー管理」にたまる
   ↓
あなたが「ステータス」を「承認」に変える
   ↓
メニュー「共同開発管理 > 承認者にフォルダを共有」
   ↓ ── Google ドライブのフォルダが Gmail 宛てに共有される
   ↓ ── Webhook で「フォルダを共有しました」

【要望・不具合】
要望フォームに入力
   ↓ ── Webhook で Discord に内容が届く（不具合は🐞赤、要望は💡黄）
スプレッドシート「要望・不具合一覧」で「対応状況」を管理
```

## ファイル

| ファイル | 内容 |
|----------|------|
| [create-form.gs](create-form.gs) | フォーム・管理シート・Discord 通知をまとめて作る Google Apps Script |
| [inquiry-tasks.gs](inquiry-tasks.gs) | 手で作った「Chrome拡張機能 お問い合わせフォーム（回答）」用の修正タスク管理。そのスプレッドシートの「拡張機能 > Apps Script」に貼って `setup` を実行 |
| [form-questions.md](form-questions.md) | 質問の一覧（手作業で作る・見直す場合） |
| [discord-post.md](discord-post.md) | Discord に貼る案内文とチャンネル構成の例 |

## 作り方

### 1. Discord の Webhook を作る

1. 通知を受けたいチャンネル（例: `#フォーム通知`、管理者だけ見られるチャンネル）の ⚙「チャンネルの編集」
2. 「連携サービス > ウェブフック > 新しいウェブフック」
3. 「ウェブフックURLをコピー」

> Webhook URL を知っている人は誰でもそのチャンネルに投稿できます。人に見せたり、コードに直接書いたりしないでください。

### 2. 共有用のドライブフォルダを作る

Google ドライブでフォルダを作り（例: `simai-overlay 開発`）、URL `https://drive.google.com/drive/folders/XXXXXXXX` の `XXXXXXXX`（フォルダ ID）を控えます。

### 3. Apps Script を用意する

1. https://script.google.com を開き「新しいプロジェクト」
2. `コード.gs` の中身を全部消して、[create-form.gs](create-form.gs) の中身を貼り付けて保存
3. 上の方の `SHARE_FOLDER_ID` にフォルダ ID を入れる（閲覧のみにしたいなら `SHARE_ROLE` を `'viewer'` に）
4. 左の ⚙「プロジェクトの設定」>「スクリプト プロパティを追加」

   | プロパティ | 値 |
   |------------|-----|
   | `DISCORD_WEBHOOK_URL` | 手順1でコピーした URL |
   | `RECRUIT_WEBHOOK_URL`（任意） | 応募の通知だけ別チャンネルにする場合 |
   | `REQUEST_WEBHOOK_URL`（任意） | 要望の通知だけ別チャンネルにする場合 |

5. 関数 `testWebhook` を選んで「実行」→ Discord に「テスト通知」が届けば OK
   - 初回は権限の確認が出るので、自分のアカウントで許可（「このアプリは Google で確認されていません」→「詳細」→「（安全ではないページ）に移動」）

### 4. フォームを作る

1. `createRecruitForm` を実行 → 募集フォームと「共同開発メンバー管理」シートができる
2. `createRequestForm` を実行 → 要望フォームと「要望・不具合一覧」シートができる
3. 「実行ログ」に出る URL を控える
   - **回答用URL** … Discord で案内する
   - **編集用URL** … フォームを直すとき
   - **シートURL** … 管理用
4. 試しに自分で両方のフォームに回答して、Discord に通知が届くか確認
5. [discord-post.md](discord-post.md) の `{募集フォームURL}` `{要望フォームURL}` を置き換えて Discord に投稿

> フォームとシートはマイドライブ直下に作られます。後から移動して大丈夫ですが、**共有用フォルダには入れないでください**（応募者の個人情報が見えてしまいます）。

> 以前の版のスクリプトでフォームを作ってしまった場合は、作り直さずに `installNotifyTriggers` を実行すれば通知だけ追加できます（要望フォームは、スクリプトプロパティ `REQUEST_SHEET_ID` に要望一覧シートの ID を入れてから実行）。

## 応募が来たら

1. Discord に通知が来る → 通知のタイトルをクリックすると管理シートが開く
2. `応募一覧` タブで内容を確認して「ステータス」を選ぶ
   - `承認` … フォルダを共有する
   - `保留` / `見送り` … 共有しない
3. メニュー **共同開発管理 > 承認者にフォルダを共有**
   - `承認` で、まだ共有していない人だけに共有。ステータスが `共有済み` になり、共有日時が入る
   - Discord にも「フォルダを共有しました」と通知される
   - メニューが出ないときはシートを再読み込み。それでも出なければスクリプトエディタで `shareFolderWithApproved` を実行（結果は実行ログに出ます）
4. 本人への連絡は、Discord の DM などで（[discord-post.md](discord-post.md) に文例あり）

## 要望が来たら

1. Discord に通知が来る（タイトル・内容・種類・関係する機能など）
2. 「要望・不具合一覧」シートで「対応状況」「担当」「対応メモ」を更新

## 修正タスク（コード修正の管理）

「要望・不具合一覧」スプレッドシートの **修正タスク** シートで、直す作業をタスクとして管理します。

### 準備

- これから要望フォームを作る場合: `createRequestForm` を実行すれば一緒にできます
- **もう要望フォームを作ってある場合**: 最新の [create-form.gs](create-form.gs) に貼り替えて保存し、`setupTaskManagement` を1回実行
  - フォームに「使っているバージョン」の質問が足されます
  - 要望一覧に「タスクID」列、「修正タスク」シートができます
  - 何度実行しても、同じものが二重にできることはありません

### 流れ

```
不具合の報告がフォームに届く
   ↓ ── 修正タスクに BUG-001 のような行が自動で増える（要望一覧の「タスクID」にも同じ番号が入る）
担当・ステータスを決める（未着手 → 対応中）
   ↓
コードを直して新しい版を配布 →「修正バージョン」に版を書き、ステータスを「確認待ち」
   ↓ ── テスターに確認をお願いする
直っていたら「完了」（完了日が自動で入る）
```

- **要望・改善もタスクにしたいとき**: 要望一覧でその行を選び、メニュー **タスク管理 > 選んだ行をタスクにする**（`REQ-001` …）。複数行を選んでもOK
- **ステータスを変えると**、要望一覧の「対応状況」も自動で合わせます（確認待ち → 対応中、保留 → 検討中）
- 色分け: 対応中は青、確認待ちはオレンジ、完了・対応しないは灰色、優先度「高」で未完了は赤字
- 見出しのフィルタで「ステータス = 未着手・対応中」などに絞れます
- 同じ不具合が2回報告されたら、片方を「対応しない」にして、対応メモに「BUG-003 と同じ」と書いておくとよいです

> 修正タスクの列見出しも名前で探しています。列の並べ替えはしてもよいですが、見出しの名前は変えないでください。

## 通知に出る内容

- **応募**: Discord 表示名・ユーザー名、参加したい内容、できること、プレイ歴など
  - **Gmail アドレスと Discord ユーザーID は通知に出しません**（シートでだけ確認）。通知先が管理者だけのチャンネルで、出してもよい場合は `create-form.gs` の `NOTIFY_INCLUDE_PRIVATE` を `true` に
- **要望**: 回答の全項目
- 回答に `@everyone` などが書かれていても、メンションにはならないようにしています

## 注意

- **Discord ID が正しいか**: 表示名・ユーザー名は変えられますが、ID は変わりません。メンバーの照合は ID で行うのが確実です。
- **Gmail のみ**: `@gmail.com` 以外は弾いています。他のアドレスも許可するなら `create-form.gs` の Gmail の正規表現を変更してください。
- **共有をやめるとき**: Google ドライブでフォルダを右クリック →「共有」からその人を削除（スクリプトでは削除しません）。シートのステータスも `見送り` などに。
- **質問名・列の見出しは変えない**: スクリプトは「Gmail アドレス」「ステータス」「種類」「タイトル（ひとことで）」「内容」などの名前で探しています。変えたら `create-form.gs` の該当箇所も合わせて直してください。
- **通知が来ないとき**: script.google.com の左メニュー「実行数」で `onRecruitSubmit` / `onRequestSubmit` のエラーを確認。「トリガー」に `onRecruitSubmit` / `onRequestSubmit` が登録されているかも確認してください。修正タスクが増えないときは `onRequestRowSubmit` / `onTaskEdit` / `onOpenRequests` も（なければ `setupTaskManagement` を実行）。
- **個人情報**: 管理シートは自分だけが見られる状態にしておいてください。
